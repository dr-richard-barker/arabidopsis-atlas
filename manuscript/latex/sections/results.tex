\subsection{Real spaceflight response, by organ}

Of the five organs modelled, one (root) has a directly tissue-matched real spaceflight
comparison: OSD-120 profiled root tissue specifically, at Day 13, under
\NumFlightSamplesOsdOneTwentyZero{} flight and \NumGroundSamplesOsdOneTwentyZero{} ground
control samples across \NumGenesOsdOneTwentyZero{} genes. The largest mean flight/ground
CPM ratio in that comparison is \TopFoldChangeOsdOneTwentyZero{} $\log_2$ units, for
\texttt{\TopGeneOsdOneTwentyZero{}}.

OSD-314 profiled whole seedlings, not a single organ, across the same
\NumGenesOsdThreeFourteen{} genes, comparing \NumMicrogSamplesOsdThreeFourteen{} real
microgravity samples against \NumGroundSamplesOsdThreeFourteen{} 1g ground samples; its
largest ratio is \TopFoldChangeOsdThreeFourteen{} $\log_2$ units, for
\texttt{\TopGeneOsdThreeFourteen{}}. Because it is not organ-specific, we report it in the
data provenance ledger rather than attach it to any single organ in the viewer, to avoid
implying a tissue-level claim the data does not support.

The remaining three organs (rosette leaf, inflorescence axis, flower/silique) have no
organ-matched spaceflight dataset wired into this version of the atlas; the viewer states
this plainly for each rather than substituting the whole-seedling numbers as if they were
organ-specific.

\subsection{Realistic geometry and real ecotype shape-morphing}

Inspecting rice-atlas's actual source (not just its file names) showed that its visual
quality comes mainly from spline-swept tube construction -- a Catmull-Rom spline plus a
parallel-transport (rotation-minimizing) frame builder -- rather than from Blender
sculpting, which it uses only for a thin Solidify-modifier pass on leaf blades. We
re-implemented the same class of technique independently in the viewer itself (a
double-reflection rotation-minimizing frame builder, \texttt{app/src/organGeometry/}),
replacing the original primitive-shape organs with tapering, curved tube geometry and a
parametric curved leaf-blade surface.

We then wired this geometry to real per-ecotype trait data so a viewer can select a
natural accession and see the plant's shape actually respond. \NumEcotypes{} ecotypes are
available; \NumMagicFounderEcotypesUsed{} of them (Col-0, Ler, Ws, Tsu-0, Edi-0) have real,
directly-computed rosette-shape descriptors from Camargo et al.\ \citeyearpar{Camargo2014}'s
own published raw data (\NRosetteImagesPerEcotype{} images per accession): mean rosette
Compactness is \ColZeroCompactness{} for Col-0, \LerCompactness{} for Ler, and
\WsCompactness{} for Ws -- \MostCompactEcotype{} is the most compact and
\LeastCompactEcotype{} the least compact of the five measured here, independently
corroborating Ler's known compact habit with an entirely different, image-based method
than the genetic literature that first described it. Ler's short pedicels and blunt
siliques reflect the real, natural \textit{erecta} (\textit{er}) mutation
\citep{Torii1996}; a quantitative proxy from \citet{Bundy2012} gives a mature wild-type
pedicel of \PedicelWildTypeMm{}mm versus a $\sim$\PedicelErShorteningFold{}$\times$ shorter
induced \textit{er-105} pedicel, disclosed in the application itself as a proxy from an
induced allele in a Columbia background, not a direct field measurement of natural Ler.
Cvi-0, absent from the MAGIC founder panel, instead varies by a real, directly-quoted
comparison from \citet{Coneva2018}: \CviExtraLeavesVsLer{} more leaves than Ler in
long-day conditions, with thicker leaf blades.

Every gap is disclosed rather than filled with a plausible value: Cvi-0's
rosette-compactness parameter defaults to the Col-0 value because no measurement exists
for it in the dataset used; ERECTA status for Cvi-0/Tsu-0/Edi-0 is stated as an assumed
default, not confirmed per-accession; and no accession-labelled reference photo was found
for Ws, so its photo link is simply absent rather than substituted.

\subsection{A real-data-driven growth animation}

A second Pages route (\texttt{growth.html}) shows a seed-to-flowering growth animation
timed to \citet{Boyes2001}'s real measured developmental stages rather than an invented
pace: \NumRealGrowthStages{} real stage transitions, from seed imbibition through
flowering complete, drive when each rosette leaf, the bolting stem, and each flower/
silique appears. \NumAnimationFrames{} frames (\AnimationDurationSeconds{}s at
\AnimationFps{}fps, \AnimationResolution{} px, \AnimationSamples{} Cycles samples) are each
an independently regenerated snapshot from the same live generator behind the interactive
viewer -- called once per frame at that frame's real day via \texttt{npx tsx
export\_growth\_frame.ts} -- rather than a single mesh interpolated or hand-animated in
Blender, on a single Apple M5 Pro (20-core GPU, Metal). This initial pass was later revised
for camera work and photorealism (see below); real total render time and per-frame cost are
reported there for the version actually shipped, rather than duplicated here for a pipeline
this repository no longer runs.

Getting this initial pass to actually finish rather than merely start surfaced two more real bugs,
neither guessed: rebuilding every material from scratch each frame crashed Cycles' own
Metal shader compiler after roughly 9 frames (confirmed from the actual crash backtrace,
which pointed directly at \texttt{ccl::MetalKernelPipeline::compile}), fixed by building
materials once and reusing them across frames; and a materials-assignment helper
unconditionally cleared every mesh's material list before reassigning it, silently
stripping the ground plane's soil material on every single frame because "the ground" -- a
persistent object outside the per-frame loop -- matched none of the organ-name rules the
helper checked. Root-growth timing in the animation has no Boyes-equivalent source (that
paper covers shoot phenotypes only) and instead follows the rosette-growth fraction as a
disclosed proxy, exactly as in the static viewer.

No claim is made that this is the most detailed 4D Arabidopsis model ever produced. The
real state of the art is genuinely fragmented across cell-lineage imaging
\citep{Fernandez2010}, whole-plant mechanistic growth modelling \citep{Chew2014}, and
whole-rosette 4D phenotyping \citep{Apelt2015,Bernotas2019}, each leading on a different axis
of "detail," with no CGI Arabidopsis growth-animation precedent found at all -- there is no
single existing bar to measure this against, so none is asserted.

\subsection{A director's pass: continuity, camera and photorealism (v2)}

Assessing the v1 animation against its own actual output -- rendered frames, not just the
code that produced them -- surfaced concrete, fixable problems rather than vague notes.
Every organ's fine-detail jitter (lateral-root angle/length, silique pedicel tilt) used
JavaScript's unseeded random generator; because each frame is regenerated in an independent
subprocess, every organ received a completely new random value every single frame even
where nothing developmentally changed, reading as shimmer rather than growth. This is fixed
with a small deterministic hash keyed to each organ's own stable index, so an organ's jitter
is identical across every frame it appears in while still varying between organs. The
inflorescence axis and each individual flower/silique also previously appeared at full size
the instant a threshold was crossed rather than growing in; both now use the same
emergence-ramp treatment rosette leaves already had. The camera itself was a single framing
computed once from the mature plant and reused for all 576 frames: inspecting actual output
frames showed the day-0 seedling occupying roughly 1-2\% of frame, and the mature plant's
inflorescence exiting the top of frame before any flower or silique was visible. The camera
now re-frames on each frame's own actual above-ground extent, eased across keyframes
anchored to real Boyes stage boundaries, with physical depth of field added -- the camera
parameter \emph{values} at each keyframe are a disclosed directorial choice, the same
"real data drives \emph{when}, technique choice drives \emph{how}" split already used for
organ emergence timing. The full v2 sequence rendered in \RenderTotalMinutes{} minutes,
averaging \RenderAvgSecondsPerFrame{}s/frame across all \NumAnimationFrames{} frames --
measured from the actual render log, not estimated; the richer materials and depth of field
added roughly 18\% to the v1 pipeline's \NumAnimationFrames{}-frame baseline time.

\subsection{A digital-twin data-overlay layer}

A real-data-driven visualization and integration layer was added over the existing
organ-selectable geometry, explicitly \emph{not} a claim to reimplement existing systems
models: AraGEM \citep{DalMolin2010} and its more recent tissue-specific descendant AraRoot,
Chew et al.'s \citeyearpar{Chew2014} whole-plant Framework Model, and BioOS
\citep{BioOS2026} -- a real, directly relevant, very recent (2026) Arabidopsis digital-twin
effort -- are cited and linked as the real existing computational layer this visualization
complements, not duplicates. NASA OSDR ingestion is generalized from the two studies already
hardcoded to any real OSD accession, verified end-to-end against OSD-522
\citep{OSD522} -- a study this repository's own limitations section had already flagged as
real and relevant but unprocessed -- yielding \NumGenesOsdFiveTwoTwo{} genes and a top
mean-CPM log2 ratio of \TopFoldChangeOsdFiveTwoTwo{} for \texttt{\TopGeneOsdFiveTwoTwo{}}
between its real flight and ground sample groups. OSD-522's own protocol describes dissecting
plants into root and shoot tissue for different assays, but its RNA-seq sample records
carry no organism-part annotation in the metadata this repository could query -- so this
comparison is reported as whole-study flight-vs-ground, explicitly not claimed as
tissue-specific, rather than guessing which tissue the 12 sequenced samples are. A real
architectural constraint was found,
not assumed: NASA OSDR's API returns \texttt{Access-Control-Allow-Origin: osdr.nasa.gov} on
every endpoint used, which a browser enforces against any other origin, so OSDR data reaches
this atlas the same way the original two studies already did -- fetched by a script and
committed as static data -- rather than a live in-browser request the deployed site could
actually serve. Real per-organ context from \citet{Lee2025} -- a single-cell and spatial
transcriptomic atlas spanning ten real developmental stages and over 400{,}000 nuclei,
seed to silique -- is linked to, not redistributed, pending confirmation of its data's
bulk-reuse terms (the same open item already carried for TraVA). A viewer's own uploaded
tissue-resolved data is parsed entirely client-side, malformed rows reported rather than
silently dropped, and matched to the nearest real day on this atlas's own Boyes-2001 axis
with the actual day gap always shown rather than a silent interpolation.

\subsection{Verification of the viewer itself}

The viewer was checked interactively, not only by static code review: in both a local
development server and the actual production build served at the live GitHub Pages URL,
clicking each organ was confirmed to open an information panel showing the correct TraVA
category, the correct geometry citation, and -- for root -- the real gene table described
above, with no console errors in either environment. The digital-twin panel's CSV upload,
parsing, validation, and day-proximity matching were confirmed against a hand-crafted test
file with one deliberately malformed row (verified reported, not silently dropped), and
every new external link (the Salk atlas tool, the GEO record, the OSDR search page) was
confirmed to resolve live before shipping.
